# 📈 Project Results

![FD001 execution results](../assets/fd001-execution-results.svg)

## 🛰️ Dataset

The project uses NASA C-MAPSS FD001, a simulated turbofan-engine degradation dataset.

There are 100 training engine trajectories and 100 test engine trajectories. Each record contains an engine ID, operating cycle, three operating settings, and 21 sensor measurements.

The test trajectories stop before simulated failure. NASA supplies the true RUL values separately so that a model can be evaluated.

## 📊 FD001 results

| Metric | Result |
|---|---:|
| Test engines | **100** |
| Test records | **13,096** |
| Training records | **20,631** |
| Mean RUL | **75.52 cycles** |
| Median RUL | **86 cycles** |
| Minimum RUL | **7 cycles** |
| Maximum RUL | **145 cycles** |
| Critical (≤30) | **25 engines** |
| High (31–60) | **14 engines** |
| Maintenance queue (≤60) | **39 engines** |
| Watch (61–90) | **15 engines** |
| Healthy (>90) | **46 engines** |

## 🔎 What the numbers mean

The mean RUL is 75.52 cycles, but the full range is 7 to 145 cycles. The lower end of the distribution is therefore more useful for prioritization than the average by itself.

The project uses 60 cycles as the maintenance-queue cutoff for this analysis. Under that rule, 39 of the 100 test engines are in the queue.

## 🔧 Engineering output

The repository produces:

- a cleaned engine-cycle data flow in PySpark
- a Gold-layer latest-engine view
- dbt models for analytical reporting
- Synapse DDL and reporting views
- a 100-engine result CSV
- a Streamlit dashboard
- Python tests and a GitHub Actions workflow

## ☁️ Current scope

The benchmark analysis is reproducible from the committed result files. The Azure folders contain the implementation files for the planned cloud flow, but this repository does not include a live Azure subscription or workspace.

That means the project can demonstrate the code, data flow, SQL, tests, and reporting without claiming that a cloud job ran when it did not.

## ⚠️ Important RUL detail

The RUL values in the test result are ground truth supplied for benchmark evaluation. They are not predictions generated by this repository.

If the project is extended into a predictive system, the dashboard should use a separately trained and evaluated model prediction instead.
